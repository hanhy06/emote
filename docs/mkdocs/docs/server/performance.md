## 측정 방식

각 지점은 `/emote stress-test 30s N N`으로 측정했다. 그래프의 `N명 상당`은 실제 플레이어 수가 아니라 다음 두 부하 값을 모두 `N`으로 설정했다는 뜻이다.

| 값              | 실제 구현에서의 의미                                                                                                                                                                                                                         |
|-----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 인스턴스 `N`    | 서버에 서로 독립된 에모트 재생기 `N`개를 만들고, 각 재생기에 필요한 디스플레이 엔티티를 실제 월드에 배치한다. 에모트는 고정 시드로 섞어 선택하고 서로 다른 재생 시점에서 시작한다. 실제 `ServerPlayer` 객체나 플레이어 연결은 만들지 않는다. |
| 패킷 fanout `N` | 변경된 디스플레이 메타데이터 패킷 하나를 인메모리 Minecraft 패킷 인코더 `N`개에 각각 넣는다. 패킷 코덱, 압축, 길이 프레이밍 비용과 생성된 바이트 수는 포함하지만, 실제 소켓 전송, 네트워크 지연, 클라이언트 디코딩·렌더링은 포함하지 않는다. |

따라서 `75명 상당`은 **75개 에모트가 동시에 재생되고 각 변경 패킷이 75명의 수신자에게 전달되는 상황에 가까운 합성 부하**다. 모든 플레이어가 같은 추적 범위에서 서로의 에모트를 보는 경우를 가깝게 모델링하지만, 실제 플레이어 75명이 접속해 사용한 결과는 아니다. 플레이어가 서로 떨어져 있거나 일부만 에모트를 사용하면 실제 fanout과 부하는 이보다 작아질 수 있다.

## 해석

- 평균 MSPT는 10명 상당 9.66 ms, 25명 상당 13.33 ms, 50명 상당 26.93 ms까지 50 ms 기준 아래에 머물렀다. 75명 상당에서는 50.66 ms로 기준을 막 넘었고, 100명 상당에서는 81.21 ms까지 상승했다. 이 서버와 테스트 구성에서는 75×75 부하부터 20 TPS를 지속하기 어려워지는 경계가 나타난다.
- 600틱은 20 TPS에서 30초가 걸린다. 10~50명 상당에서는 전체 시간이 30초로 유지됐지만 75명 상당에서는 32.0초, 100명 상당에서는 51.4초로 늘어 서버가 목표 틱 속도를 유지하지 못했다.
- 부하가 커질수록 `Server/idle`이 줄고 `Network`가 1.0초에서 41.3초까지 증가했다. 100명 상당에서는 전체 51.4초 중 약 80%를 차지하므로, 주된 병목은 에모트 타임라인 계산보다 변경 감지와 패킷 직렬화·압축이다.
- 이 결과로 실제 서버의 최대 접속 인원을 바로 정할 수는 없다. 실제 한계는 동시에 에모트를 사용하는 비율, 플레이어 간 추적 범위, 에모트별 디스플레이 수, 서버 CPU, 압축 설정, 다른 모드와 월드 부하에 따라 달라진다.
- 테스트 장비의 24 GB 메모리가 싱글 채널로 구성되어 있어 메모리 대역폭이 고부하 결과에 영향을 주었을 가능성이 있다. 듀얼 채널 구성과의 비교 측정은 하지 않았으므로 영향의 크기를 특정하거나 주된 병목으로 단정할 수는 없다.
