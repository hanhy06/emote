# Emote Animation JSON 명세 초안

이 문서는 [`emote-animation-format.json`](./emote-animation-format.json)의 각 필드가 무엇을 의미하고 서버 런타임이 어떻게 해석해야 하는지 정의한다.

예제 JSON은 기능을 보여 주는 데이터이고, 이 문서는 구현 규칙이다. 별도로 명시하지 않은 동작은 예제의 우연한 값에 의존하지 않는다.

## 1. 설계 범위

- 대상 Minecraft 버전은 26.1 이상이다.
- 애니메이션 시간은 Minecraft 서버 tick과 같은 20 TPS로 고정한다.
- 플레이어 모델뿐 아니라 Item Display, Block Display, Text Display, 효과 위치용 Anchor를 함께 다룬다.
- 소리, 파티클, 커맨드는 별도 전용 형식으로 재해석하지 않고 원본 Minecraft 커맨드를 보존한다.
- BD Engine 데이터팩, BD Engine 프로젝트, Animated Java 출력 등은 변환기의 입력 형식일 뿐이다. 서버는 변환된 이 JSON만 실행한다.
- 리소스팩 배포는 스키마 버전 1의 범위 밖이다. JSON에서 사용하는 아이템 모델과 리소스는 서버가 배포한 리소스팩에 이미 존재해야 한다.

## 2. 규범 용어

이 문서의 **필수**는 파일 또는 런타임이 반드시 지켜야 하는 규칙을 뜻한다. **권장**은 특별한 이유가 없다면 따라야 하는 규칙이다.

시간 값은 모두 정수 tick이다. 실수 초 단위 시간은 저장하지 않는다.

## 3. 루트 필드

### `schema_version`

JSON 구조의 버전이다. 현재 값은 `1`이다.

런타임은 지원하지 않는 스키마 버전을 추측해서 읽지 않고 로드를 거부해야 한다. 하위호환은 기본 목표가 아니다.

### `minecraft_version`

이 파일을 생성하고 검증한 정확한 Minecraft 버전이다. 최소 지원 버전이 아니다.

SNBT, 아이템 컴포넌트, 엔티티 태그, 커맨드 문법이 Minecraft 버전에 따라 바뀔 수 있으므로 스키마 버전 1 런타임은 서버 버전과 값이 정확히 일치하는 파일만 로드한다.

예를 들어 `"minecraft_version": "26.2"`는 Minecraft 26.2용 파일이라는 의미다.

### `tick_rate`

애니메이션 작성 기준 tick rate다. 스키마 버전 1에서는 반드시 `20`이어야 한다.

논리 tick은 서버 tick마다 하나씩 증가한다. 서버가 렉으로 느려지더라도 중간 애니메이션 tick을 건너뛰어 실제 시간에 따라잡지 않는다.

### `id`

애니메이션의 논리적 식별자다. Minecraft 리소스 위치와 같은 `namespace:path` 형식을 사용한다.

- 서버에 동시에 로드된 애니메이션 사이에서 유일해야 한다.
- 파일 내용이 수정되어도 같은 애니메이션이면 `id`는 유지한다.
- 캐시 변경 감지용 해시로 사용하지 않는다.

### `metadata`

표시와 실행에 필요한 부가 정보다.

| 필드 | 의미 |
|---|---|
| `name` | 메뉴와 로그에 표시할 이름 |
| `description` | 애니메이션 설명 |
| `hide_player` | 재생 중 원래 플레이어 모델을 숨길지 여부 |

`hide_player`가 참이면 런타임은 애니메이션 시작 후 플레이어를 숨기고, 정상 종료·이동 취소·오류 종료를 포함한 모든 정리 경로에서 반드시 원래 상태를 복구해야 한다.

## 4. 원점과 좌표계

### 내부 루트

루트는 JSON 노드가 아니라 재생 인스턴스가 가진 내부 좌표계다. 따라서 루트 설정 필드는 JSON에 두지 않는다.

재생을 시작할 때 다음 값으로 루트를 한 번 생성한다.

- 위치: 플레이어의 시작 월드 위치
- 회전: 플레이어가 시작할 때 바라보던 수평 방향
- pitch: 반영하지 않음
- 크기: `1`

로컬 `+Y`는 위쪽이다. 로컬 `+Z`는 시작 시 플레이어가 바라보던 수평 방향이다. 런타임은 Minecraft 월드 좌표계에 맞게 루트 변환을 구성한다.

루트는 재생 중 플레이어를 따라가지 않는다. 플레이어의 위치 이동, 차원 이동 또는 탑승 상태 변화는 애니메이션 취소 조건이다. 시선만 돌리는 것은 루트를 바꾸지 않는다.

### `transform_space`

| 필드 | 스키마 버전 1의 값 | 의미 |
|---|---|---|
| `coordinate_space` | `root_local` | 모든 노드 행렬은 내부 루트 기준 |
| `matrix_layout` | `row_major` | 배열을 행 우선 순서로 저장 |
| `matrix_size` | `16` | 4×4 행렬 |

행렬은 열 벡터에 곱하는 4×4 변환 행렬이다. 배열의 인덱스 `3`, `7`, `11`이 각각 X, Y, Z 이동값이다.

```text
[ m00, m01, m02, tx,
  m10, m11, m12, ty,
  m20, m21, m22, tz,
  m30, m31, m32, tw ]
```

노드의 월드 변환은 `root_matrix × node_matrix`로 계산한다. 스키마 버전 1에는 부모·자식 노드 계층이 없으며 모든 노드는 루트 직속이다.

행렬은 이동, 회전, 크기, 기울이기를 함께 표현할 수 있다. 런타임은 행렬을 임의로 TRS로 분해했다가 다시 조합하여 원래 값을 손실하면 안 된다.

## 5. 노드

`nodes`는 노드 ID를 키로 사용하는 객체다. 노드 ID는 한 애니메이션 안에서 유일해야 하며 키프레임과 이벤트에서 이 ID를 참조한다.

모든 노드는 `type`과 16개 숫자로 된 `default_matrix`를 가져야 한다. `default_matrix`는 tick 0 이전과 루프 초기화 때 사용하는 기본 변환이다.

### 공통 필드

| 필드 | 의미 |
|---|---|
| `type` | 노드 종류 |
| `visible` | 최초 가시성. 생략하면 `true` |
| `default_matrix` | 루트 기준 기본 4×4 행렬 |
| `entity_nbt` | 엔티티를 만들 때 추가로 적용할 Compound SNBT |

`entity_nbt`는 완전한 엔티티 저장본이 아니라 초기 추가 데이터다. 런타임은 다음처럼 자신이 소유하는 필드를 우선한다.

- 엔티티 종류와 UUID
- 월드 위치, 이동량과 회전
- display transformation과 interpolation 관련 값
- 런타임 식별용 태그
- 노드별 표시 데이터 필드

따라서 `entity_nbt`에 이 필드가 들어 있어도 런타임이 계산한 값으로 덮어쓴다. 그 밖의 유효한 NBT는 가능한 한 원형대로 적용한다. 동적 NBT 변경은 이벤트의 원본 커맨드로 수행한다.

### `item_display`

Item Display 엔티티를 생성한다.

| 필드 | 의미 |
|---|---|
| `item_stack_snbt` | 표시할 ItemStack 전체 SNBT. 컴포넌트와 인챈트 포함 |
| `item_display` | vanilla Item Display 표시 컨텍스트 |
| `skin` | 재생 플레이어 스킨으로 교체할 조각 정보 |

`skin.part`는 `head`, `body`, `left_arm`, `right_arm`, `left_leg`, `right_leg` 중 하나다. 같은 부위가 여러 조각이면 `skin.order`의 오름차순이 몸 중심에서 바깥쪽 순서다.

### `block_display`

Block Display 엔티티를 생성한다. `block_state_snbt`에 전체 블록 상태 SNBT를 저장한다.

### `text_display`

Text Display 엔티티를 생성한다. `text`는 문자열로 직렬화한 SNBT가 아니라 JSON 텍스트 컴포넌트 객체다. 나머지 Text Display 속성은 `entity_nbt`에 저장할 수 있다.

### `anchor`

효과와 커맨드 위치를 지정하기 위한 논리 노드다. 엔티티를 소환하지 않으며 렌더링되지 않는다.

- `default_matrix`와 키프레임 변환을 가질 수 있다.
- 이벤트의 `origin`으로 사용할 수 있다.
- 실제 엔티티가 없으므로 이벤트의 `source`로 사용할 수 없다.
- `visible`과 `entity_nbt`는 사용하지 않는다.

## 6. 가시성

`visible`은 엔티티의 존재 여부가 아니라 렌더링 여부다. 런타임은 가시성을 바꿀 때마다 엔티티를 제거하거나 멀리 순간이동시키지 않는다.

- Item Display: 표시 ItemStack을 비워 숨긴다.
- Block Display: 표시 상태를 air로 바꿔 숨긴다.
- Text Display: 표시 텍스트를 비워 숨긴다.
- Anchor: 가시성의 영향을 받지 않는다.

숨길 때 런타임은 해당 표시 데이터를 보관하고 다시 보일 때 복원한다. 일반 엔티티의 `Invisible` NBT는 Display 엔티티 렌더링을 보장해서 끄지 않으므로 가시성 구현에 사용하지 않는다.

숨겨진 노드도 엔티티 자체는 유지되므로 이벤트의 `source`가 될 수 있다. 다만 숨겨진 동안 원본 커맨드로 그 노드의 item, block_state 또는 text를 직접 변경하는 동작은 정의하지 않는다. 변환기는 이런 변경과 `visible: false` 구간이 겹치지 않도록 해야 한다.

## 7. 타임라인

### `duration_ticks`

애니메이션의 종료 경계 tick이다.

- 키프레임 tick 허용 범위: `0..duration_ticks`
- 타임라인 이벤트 tick 허용 범위: `0..duration_ticks - 1`
- `duration_ticks` 시점의 키프레임은 최종 자세를 정의할 수 있지만 그 시점에 새 타임라인 이벤트를 실행하지 않는다.

### `loop`

스키마 버전 1은 다음 값을 지원한다.

| 값 | 동작 |
|---|---|
| `once` | 종료 경계에서 정지 |
| `loop` | 종료 경계에서 다시 tick 0으로 이동 |
| `server_sync` | 서버의 공통 게임 시간을 기준으로 재생 위치를 맞추며 무한 반복 |

### `loop_delay_ticks`

`loop` 또는 `server_sync`일 때 반복 사이에 최종 상태를 유지할 tick 수다. `once`에서는 반드시 `0`으로 취급한다.

`server_sync`의 주기 길이는 `duration_ticks + loop_delay_ticks`다. 재생을 시작할 때 서버의 공통 게임 시간을 주기 길이로 나눈 나머지를 현재 위치로 사용한다. 중간 위치에서 시작하면 이미 지나간 `timeline`과 `loop` 이벤트는 실행하지 않고, 이후 도달하는 이벤트부터 정상 실행한다. `start` 이벤트는 실제 재생 시작 시 한 번 실행한다.

### `keyframes`

키프레임 배열은 `tick` 오름차순이어야 한다. 하나의 키프레임은 해당 tick에서 목표로 하는 노드 변환과 즉시 바뀌는 노드 상태를 담는다.

```json
{
  "tick": 40,
  "interpolation_duration_ticks": 5,
  "node_transforms": {
    "caption": {
      "matrix": [1, 0, 0, 0, 0, 1, 0, 2.6, 0, 0, 1, 0, 0, 0, 0, 1]
    }
  },
  "node_states": {
    "caption": {
      "visible": true
    }
  }
}
```

#### 누락된 노드 값

- `node_transforms`에 노드가 없으면 그 노드의 직전 유효 변환을 유지한다.
- 해당 노드의 첫 변환 키프레임 전에는 `default_matrix`를 유지한다.
- `node_states`에 노드가 없으면 직전 상태를 유지한다.
- 해당 노드의 첫 상태 키프레임 전에는 노드 정의의 `visible` 값을 사용한다.
- 누락은 기본값으로 재설정한다는 뜻이 아니다.

#### 보간 기준

`interpolation_duration_ticks`는 **현재 목표 키프레임에 도달하기 직전의 보간 길이**다. 이후 키프레임을 향하는 시간이 아니다.

목표 tick이 `T`, 보간 시간이 `D`라면 직전 유효 변환을 `T - D`까지 유지하고, `T - D`부터 현재 키프레임의 행렬로 보간하여 `T`에 정확히 도달한다.

- `D = 0`: tick `T`에서 즉시 변경한다.
- 키프레임 수준의 값: 그 키프레임의 모든 `node_transforms`에 적용하는 기본값이다.
- 노드 변환 내부의 값: 해당 노드에만 적용하며 키프레임 수준 값을 덮어쓴다.
- `node_states`는 보간하지 않고 tick `T`에서 즉시 적용한다.

노드별 보간 구간은 그 노드의 직전 변환 키프레임보다 앞에서 시작할 수 없다. 즉 `D`는 현재 tick과 해당 노드의 직전 변환 키프레임 tick 차이 이하여야 한다. 첫 변환 키프레임에서는 tick 0의 `default_matrix`를 이전 값으로 취급한다.

스키마 버전 1의 행렬 보간 방식은 런타임이 사용하는 Minecraft Display 변환 보간을 기준으로 한다. 변환기는 원본 곡선을 보존하기 위해 필요하면 중간 키프레임을 추가해야 한다. 별도 easing 필드는 스키마 버전 1에 없다.

## 8. 이벤트와 원본 커맨드

`timeline.events`는 다음 네 수명주기 배열을 가질 수 있다.

| 배열 | 실행 시점 |
|---|---|
| `start` | 최초 재생 준비가 끝난 뒤 한 번 |
| `timeline` | 각 항목의 `tick`에서 실행 |
| `loop` | 반복의 종료 경계에서 한 번 |
| `stop` | 노드를 제거하기 직전에 한 번 |

이벤트 배열과 각 이벤트의 `commands` 배열은 작성된 순서를 그대로 보존한다. 커맨드 문자열에는 앞쪽 `/`를 넣지 않는다.

### `source`

커맨드의 실행 주체와 `@s`를 결정한다.

| `source.type` | 실행 주체 |
|---|---|
| `player` | 애니메이션을 재생한 플레이어 |
| `server` | 서버 커맨드 소스. 연결된 엔티티가 없으므로 `@s` 엔티티를 가정할 수 없음 |
| `node` | `source.node`가 가리키는 실제 Display 엔티티 |

`source.type: node`에는 `source.node`가 필수이며 Anchor를 참조할 수 없다.

### `origin`

커맨드의 실행 위치를 보정한다. 실행 주체는 바꾸지 않는다.

| `origin.type` | 기준 위치 |
|---|---|
| `root` | 고정 내부 루트 |
| `node` | `origin.node`의 현재 변환 위치. Anchor도 허용 |

`offset`은 기준의 로컬 좌표로 해석한 `[x, y, z]`다. 생략하면 `[0, 0, 0]`이다. 런타임은 기준 행렬로 offset을 월드 좌표로 변환한 뒤 커맨드 소스의 위치만 바꾼다. 커맨드 소스의 회전은 자동으로 바꾸지 않는다.

### 같은 tick의 실행 순서

한 tick에서는 다음 순서를 지킨다.

1. 해당 시점까지의 보간 결과를 계산한다.
2. 해당 tick의 `node_transforms` 목표와 `node_states`를 반영한다.
3. 해당 tick의 `timeline` 이벤트를 배열 순서대로 실행한다.

따라서 이벤트가 노드를 origin으로 사용하면 같은 tick의 키프레임이 반영된 위치를 본다.

### 커맨드 검증과 변환

- 로더는 `minecraft_version`에 맞는 서버 커맨드 파서로 모든 커맨드를 로드 시점에 검증해야 한다.
- 커맨드 하나라도 파싱할 수 없으면 애니메이션 전체를 등록하지 않는다.
- 런타임은 문자열을 임의로 수정하지 않고 실행 위치와 실행 주체만 구성한다.
- 데이터팩을 제거한 뒤에는 원본 `function`과 `schedule function` 대상이 존재하지 않는다. 변환기는 함수 내용을 `commands`에 인라인하거나 애니메이션 키프레임·이벤트로 변환해야 한다.
- 임의 커맨드가 변경한 월드, 플레이어, 스코어보드 등의 외부 상태는 런타임이 자동으로 되돌리지 않는다.

## 9. 재생 수명주기

### 최초 시작

1. 파일 전체를 검증하고 필요한 SNBT와 커맨드를 미리 파싱한다.
2. 플레이어 위치와 수평 방향으로 고정 루트를 만든다.
3. Display 엔티티를 생성하고 Anchor의 논리 상태를 만든다.
4. 각 노드의 초기 표시 데이터, `entity_nbt`, `default_matrix`, `visible`을 적용한다.
5. tick 0 키프레임을 적용한다.
6. `start` 이벤트를 실행한다.
7. tick 0의 `timeline` 이벤트를 실행한다.

### 반복

`duration_ticks` 경계에 도달하면 다음 순서로 처리한다.

1. 최종 키프레임 상태에서 `loop` 이벤트를 실행한다.
2. `loop_delay_ticks` 동안 최종 상태를 유지한다.
3. 런타임이 소유한 각 노드의 표시 데이터, 추가 NBT, 변환과 가시성을 노드 정의의 초기값으로 복원한다.
4. tick 0 키프레임을 적용한다.
5. tick 0의 `timeline` 이벤트를 실행하고 다음 반복을 시작한다.

`start` 이벤트는 반복하지 않는다. 노드 복원은 런타임 소유 엔티티만 대상으로 하며 원본 커맨드가 만든 외부 부작용은 복원하지 않는다.

`server_sync`도 같은 반복 절차를 사용하지만 각 플레이어의 시작 위치는 서버의 공통 게임 시간으로 결정한다. 따라서 같은 주기 길이를 가진 `server_sync` 애니메이션은 실행 시점이 달라도 같은 재생 위치를 유지한다.

### 종료

정상 종료와 취소 모두 다음 순서를 지킨다.

1. `stop` 이벤트를 한 번 실행한다.
2. 생성한 Display 엔티티와 논리 Anchor를 정리한다.
3. 플레이어 숨김 등 재생 중 변경한 플레이어 상태를 복구한다.

노드를 만들기 전에 로드가 실패한 경우에는 `stop` 이벤트를 실행하지 않는다. 재생이 시작된 뒤 런타임 오류가 발생하면 가능한 범위에서 같은 정리 절차를 수행한다.

## 10. 해시와 캐시

JSON에는 MD5나 콘텐츠 해시 필드를 저장하지 않는다.

- `id`는 논리적 식별자다.
- 서버는 파일을 로드할 때 UTF-8 원본 바이트의 SHA-256을 계산한다.
- 전체 SHA-256은 캐시 일치와 변경 감지에 사용한다.
- 앞 16개 16진수 문자는 로그와 디버그 화면에 표시하는 짧은 지문으로만 사용한다.
- 짧은 지문만으로 파일의 유일성이나 보안을 판단하지 않는다.

공백이나 필드 순서만 바뀌어도 원본 바이트가 달라지므로 해시는 달라진다. 이는 파일 변경 감지 용도에 맞는 동작이다. `id`가 같은 새 해시를 로드하면 같은 애니메이션의 새 내용으로 취급한다.

## 11. 로드 시 필수 검증

로더는 적어도 다음 조건을 검사해야 한다.

- 루트 JSON 값과 필수 필드의 자료형
- 지원하는 `schema_version`
- 서버와 일치하는 `minecraft_version`
- `tick_rate == 20`
- 유효하고 중복되지 않는 `id`
- 지원하는 노드 종류와 노드별 필수 데이터
- 모든 행렬이 유한한 숫자 16개인지 여부
- 모든 노드 참조가 존재하는지 여부
- Anchor가 이벤트 source로 사용되지 않았는지 여부
- 키프레임 정렬, tick 범위와 보간 구간의 유효성
- 이벤트 tick 범위
- SNBT와 텍스트 컴포넌트 파싱
- 모든 원본 커맨드 파싱

검증에 실패한 파일은 일부 기능만 생략해서 실행하지 않고 애니메이션 전체를 등록하지 않는다. 오류 로그에는 `id`, 파일 경로와 실패한 필드 경로를 포함하는 것을 권장한다.

## 12. 변환기 책임

입력 형식별 차이는 서버 런타임이 아니라 웹 변환기가 정리한다.

- BD Engine의 10 FPS 프레임을 정확한 20 TPS 키프레임으로 변환한다.
- Animated Java의 시간과 보간 정보를 이 명세의 tick과 목표 키프레임 기준으로 변환한다.
- 원본 행렬과 피벗 변환을 `root_local` 4×4 행렬로 합성한다.
- 노드 생성과 변경 커맨드를 노드 정의, 키프레임, 상태 또는 이벤트로 분류한다.
- 데이터팩 함수 호출은 인라인하거나 구조화된 타임라인으로 펼친다.
- 가시성 구현용 원거리 순간이동은 `node_states.visible`로 바꾼다.
- 원본 커맨드에서 상대 좌표의 기준이 필요한 경우 알맞은 `source`와 `origin`을 생성한다.
- 변환 결과에 정확한 대상 `minecraft_version`을 기록한다.

서버 런타임은 입력 도구의 종류를 알 필요가 없어야 한다.
